# Lesson 17 — Authentication & Authorization

# What Is Authentication

Authentication verifies who the user is.

```text
User
 ↓
Login
 ↓
Username + Password
 ↓
Authentication
 ↓
User Identity Verified
```

Common authentication mechanisms include:

- Username and password
- JWT
- OAuth 2.0
- OpenID Connect
- Social login

# What Is Authorization

Authorization determines what an authenticated user is allowed to do.

```text
Authentication
      ↓
Who are you?
      ↓
Siraj
      ↓
Authorization
      ↓
What can you access?
      ↓
Customer Management
```

A user may be authenticated but still not have permission to access a particular resource.

# Authentication vs Authorization

| Authentication | Authorization |
|---|---|
| Verifies identity | Verifies permissions |
| Answers "Who are you?" | Answers "What can you access?" |
| Happens during login | Happens after identity is established |
| Example: username/password | Example: ADMIN can delete users |
| Produces authenticated identity | Determines allowed actions |

# JWT

JWT stands for JSON Web Token.

A JWT is commonly used to represent authenticated user information between a client and server.

A JWT typically contains:

```text
Header
.
Payload
.
Signature
```

Example structure:

```text
xxxxx.yyyyy.zzzzz
```

The client can send the JWT with subsequent API requests:

```http
Authorization: Bearer <token>
```

# JWT Authentication Flow

```text
Angular Application
        ↓
Login
        ↓
Authentication API
        ↓
Username + Password
        ↓
JWT Token
        ↓
Angular
        ↓
Store Token
        ↓
HTTP Interceptor
        ↓
Authorization: Bearer <token>
        ↓
Protected API
```

### Step 2 — Create the Authentication Service

Open:

```text
src/app/services/auth.ts
```

Use:

```typescript
import {
  Injectable,
  signal
} from '@angular/core';

@Injectable({
  providedIn: 'root'
})
export class Auth {

  private authenticated =
    signal(false);

  private token =
    signal<string | null>(null);

  private role =
    signal<string | null>(null);

  login(
    username: string,
    password: string
  ): boolean {

    if (
      username === 'admin' &&
      password === 'admin123'
    ) {

      this.token.set(
        'demo-jwt-token'
      );

      this.role.set('ADMIN');

      this.authenticated.set(true);

      localStorage.setItem(
        'token',
        'demo-jwt-token'
      );

      localStorage.setItem(
        'role',
        'ADMIN'
      );

      return true;
    }

    return false;
  }

  logout(): void {

    this.authenticated.set(false);

    this.token.set(null);

    this.role.set(null);

    localStorage.removeItem('token');

    localStorage.removeItem('role');
  }

  isAuthenticated(): boolean {

    return this.authenticated();
  }

  getToken(): string | null {

    return this.token();
  }

  getRole(): string | null {

    return this.role();
  }
}
```

The service is responsible for:

- Login
- Logout
- Authentication state
- Token management
- Role management

# Route Guard

A route guard controls whether navigation to a route is allowed.

The authentication guard will prevent unauthenticated users from opening the dashboard.

### Step 7 — Create the Authentication Guard

Open:

```text
src/app/guards/auth-guard.ts
```

Use:

```typescript
import {
  inject
} from '@angular/core';

import {
  CanActivateFn,
  Router
} from '@angular/router';

import {
  Auth
} from '../services/auth';

export const authGuard: CanActivateFn =
  () => {

    const auth =
      inject(Auth);

    const router =
      inject(Router);

    if (auth.isAuthenticated()) {

      return true;
    }

    return router.createUrlTree([
      '/login'
    ]);
  };
```

The guard checks:

```typescript
auth.isAuthenticated()
```

If the user is authenticated:

```typescript
return true;
```

Otherwise:

```typescript
return router.createUrlTree([
  '/login'
]);
```

The user is redirected to the login page.

# Authentication Interceptor

The interceptor can add the authentication token to outgoing HTTP requests.

### Step 10 — Create the Authentication Interceptor

Open:

```text
src/app/interceptors/auth-interceptor.ts
```

Use:

```typescript
import {
  HttpInterceptorFn
} from '@angular/common/http';

export const authInterceptor: HttpInterceptorFn =
  (req, next) => {

    const token =
      localStorage.getItem('token');

    if (!token) {

      return next(req);
    }

    const modifiedRequest =
      req.clone({
        setHeaders: {
          Authorization:
            `Bearer ${token}`
        }
      });

    return next(
      modifiedRequest
    );
  };
```

The interceptor:

1. Reads the token.
2. Checks whether a token exists.
3. Clones the request.
4. Adds the `Authorization` header.
5. Sends the modified request.

The request becomes:

```http
Authorization: Bearer demo-jwt-token
```

# Role-Based Authorization

Authentication answers:

```text
Is the user logged in?
```

Authorization answers:

```text
What is the user allowed to access?
```

For example:

```text
ADMIN
 ├── View customers
 ├── Create customers
 ├── Update customers
 └── Delete customers

USER
 ├── View customers
 └── Update own profile
```

# Role Guard

A role guard can check whether an authenticated user has the required role.

### Step 12 — Create a Role Guard

Create:

```bash
ng g guard guards/role
```

Open:

```text
src/app/guards/role-guard.ts
```

Use:

```typescript
import {
  inject
} from '@angular/core';

import {
  CanActivateFn,
  Router
} from '@angular/router';

import {
  Auth
} from '../services/auth';

export const roleGuard =
  (requiredRole: string): CanActivateFn =>
  () => {

    const auth =
      inject(Auth);

    const router =
      inject(Router);

    if (
      auth.isAuthenticated() &&
      auth.getRole() === requiredRole
    ) {

      return true;
    }

    return router.createUrlTree([
      '/unauthorized'
    ]);
  };
```

# Important Security Note

The authentication example above is intentionally simplified for learning.

The application is not actually validating credentials against a backend.

The demo token:

```text
demo-jwt-token
```

is not a real JWT.

In a real application:

```text
Angular
   ↓
Login API
   ↓
Authentication Server
   ↓
Validate Credentials
   ↓
Issue JWT
   ↓
Angular
   ↓
Protected API
```

The backend must perform the actual authentication and authorization.

# JWT Token Handling

In a real application, the backend might return:

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIs...",
  "tokenType": "Bearer",
  "expiresIn": 3600
}
```

Angular can then use the access token for subsequent API requests.

The interceptor can attach it:

```typescript
const modifiedRequest =
  req.clone({
    setHeaders: {
      Authorization:
        `Bearer ${token}`
    }
  });
```

# Key Takeaways

- Authentication verifies the identity of a user.
- Authorization determines what an authenticated user can access.
- JWT is commonly used for token-based authentication.
- Authentication and authorization are different concepts.
- HTTP interceptors can attach authentication tokens to requests.
- Route guards can protect Angular routes.
- Functional guards can be created with `CanActivateFn`.
- Roles can be used for role-based authorization.
- A protected route can require authentication and a specific role.
- Authentication should ultimately be handled by a trusted backend or identity provider.
- Client-side guards improve navigation control but must not be treated as the only security mechanism.
- Real applications should validate tokens and permissions on the server.
